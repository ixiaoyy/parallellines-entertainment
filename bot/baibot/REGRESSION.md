## 专用付费网关合同

- `openai-compatible` 静态角色配置的 `base_url` 固定为 `https://api.pingxingxian.space/tavern-flux/v1`，`api_key` 由该角色的服务令牌提供。模型接口仅 `POST /tavern-flux/v1/chat/completions`，不得使用付款人、Matrix 或普通用户凭据；缺少付费事件来源时不发请求。
- `Authorization` 为服务 Bearer；`X-Tavern-Room-Id` 与 `X-Tavern-Event-Id` 来自同一个经 Matrix SDK 实际解密且通过触发检查的事件。这两个值不进模型正文。关闭请求重试和重定向，不降级到普通 `/v1`。
- 普通成员、免费 Bot 和已有 Matrix 邀请流程不经此付费接口。直接在 Matrix 邀请 Flux 并不授予房间额度；尚未启用或撤销授权的房间，由付费网关在模型/计费前拒绝。

## 原生聊天与费用边界

在独立 Bot 账号与获准测试房中，按以下顺序验证；开启真实模型调用前先核专用令牌的模型限制和总额。不要用真实聊天内容验证。

| 操作 | 预期 |
| --- | --- |
| 邀请同一角色加入两个不同的邀请制加密房；分别使用有原生邀请权限的成员 | Bot 在两个房间分别成为成员；不发欢迎消息，不影响其他成员。 |
| 向角色发出公开房、未加密邀请制房的邀请 | 两者都不加入；无模型调用。 |
| 两个合格房间分别发送不同的真实 `@`，再发普通聊天、仅手写名字、附件、编辑；加密房内另注入一条未加密的合成 `m.text` | 仅 SDK 成功解密的真实 `@` 文本触发。回复只在对应房间，模型只收到角色设定和该条新增纯文本。 |
| 在回复及线程中真实 `@` 角色 | 普通回复关联本条触发消息，线程回复留在原线程；模型不收到旧引用或其他消息。 |
| 同房 10 秒内多次触发；另一个房间在模型空闲时触发；同一事件重送 | 同房第二次不调用模型；另一房独立计时；全局最多一个模型请求在途。忙碌或限频提示不排队，重复事件无第二次回复或计费。 |
| Bot 在一个房间被移出，然后重启；另一个房间仍保留成员资格 | 被移出的房间不自动重入、不回复；仍为成员的房间继续可用。不处理启动或加入前的历史。 |
| 断线期间发邀请，恢复连接后留意已加入和待处理的房间；一个房间改为公开 | 有正面合格证据的原生待处理邀请可继续；原生正式状态变为公开后不再转发模型请求。 |
| 在启用付费邀请门禁时尝试直接邀请 Flux；随后分别用已撤销授权、房间额度/余额不足及触发上游限频的测试条件 `@` | 没有费用确认的直接邀请被拒绝，普通成员仍原生邀请；网关拒绝撤销房和额度不足房并提示。`403`、`402` 不调用模型或扣费，失败不转发上游正文、不回退。 |
